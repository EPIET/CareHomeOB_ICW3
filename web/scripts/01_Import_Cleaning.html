Among the very first things you should check for any dataframe is variable class, and its implications. Numeric variables coded as character, or viceversa. Dates as characters. Characters that should have an order - factors.

The other key issue is about extreme or implausible values for your variables. This will depend on every variable, of course, but a classical one are age values. Also, don’t forget categories within character values. All of them should be explored before running into any further analysis.

2. Data Cleaning

Fixing age

Look at the range of age: some values are clearly impossible, and likely represent typos or writing mistakes. Decide, for each implausible value, whether it’s an obvious typo you can confidently correct, or one you can’t.

Action — Tables are more than outputs for other people. They assist you during your work. For example, try to cross-tabulate age and group to find about about the nature of the mistakes, and get inspired about potential solutions.

Action — Clean accordingly to the previous step using case_when() and the adequate conditions so only the affected rows are modified. Start working on a new object named clean. Would you apply the same fix when the same implausible value affects a resident and a family member?

See the solution 
# Crosstabulate age and group using janitor to find inplausible values
raw %>% tabyl(age, group)

# Fix the age variable whit case_when()
clean <- raw %>% 
  mutate(age = case_when(
    # negative age value to positive
    age == -35  ~ 35, 
    # if 190 years and family member, assume 19 years typo
    age == 190 & group == "family"  ~ 19, 
    # if 190 years and resident, assume 90 years typo
    age == 190 & group == "resident"  ~ 90,
    # everyone else stays the same
    .default = age
  ))

Not every bad value has an obvious fix. A rule like “correct it if the error is unambiguous (an extra digit, a stray minus sign); set it to NA if you’d just be guessing” is a defensible, explicit policy - and one you can state in a line of code, not just in your head.

Hadn’t you cross-tabulated by group first, relying only on the age range, your fixing may have looked different. Use the information available whenever possible.

Fixing dates

We learned about working with dates using lubridate and how the available functions are chose based on our date variable structure, e.g. year-month-day for a “2026-09-13” date. Even if our date variable is in text format, the same logic remains. But what to do with the starthour variable? Once again, lubridate is prepared to handle that with an hours() function

Action — Change the variable class of dayonset and starthour to <date> format using lubridate. Include it in your clean object you started before

See the solution

You can include this cleaning step by either updating the clean object from the previous step or by adding it with a pipe in the first cleaning chain starting with raw.

# Update the clean object from before
clean <- clean %>% 
  mutate(
    dayonset = dmy(dayonset),
    starthour = hours(starthour)
  ) 


# Or add a new pipe to your cleaning chain
clean <- raw %>% 
  mutate(age = case_when(
    # negative age value to positive
    age == -35  ~ 35, 
    # if 190 years and family member, assume 19 years typo
    age == 190 & group == "family"  ~ 19, 
    # if 190 years and resident, assume 90 years typo
    age == 190 & group == "resident"  ~ 90,
    # everyone else stays the same
    .default = age
  )) %>% 
  # Fix dates format
  mutate(
    dayonset = dmy(dayonset),
    starthour = hours(starthour)
  )

Fixing symptoms and food variables

Interestingly, we have a fair number of columns that are coded the same:

  • Symptoms and Food are binary 0-1 (yes or no) columns

  • FoodD columns indicate the amount of the consumed food, all of them range between 0 (no or very little consumption) to 3 (more than 1 piece)

Fixing them one by one inside a massive mutate is possible, sure. But also extremely boring, problematic and subject to writing typos because of repetition. We can do better using the Tidyverse helper function across(), that facilitates applying the same transformation to multiple columns at once inside mutate()and summarise() calls

It works by specifying a set of colums and the function to apply to all of them, like this:

clean <- raw %>% 
  mutate(across(                           # direct call without a name
    .cols = c(var1, var2, var5, var14),    # set of variables to modify
    .fns = ~ as.character(.)    # we use a tilde (~) to declare the function
  ))                            # and a point (.) to indicate data from .cols

To declare the columns to modify, you can use more helper functions that answer to the question “Which of the existing variables are picked?”. The answer can be: “all of these variables”, “only those of class character”, “those that begin with the character ‘date_’”, “those that has a letter ”D” at the end of their name”… and so on [pure grammar model, isn’t it?]

Change all variables inside a vector

To begin with, we create a vector binary_cols that contains the name of all the binary 0-1 variables in our data we want to change:

binary_cols <- c("diarrhoea", "vomiting", "abdo", "fever", "nausea",
                 "buffet")

Now we will use the selecting function all_of() to declare the columns to modify inside across(). The function to apply will be factor() over all of them. Remember to include the arguments levelsand labels to indicate 0 = “No” and 1 = “Yes”

Action — Convert all of the binary variables to labelled factors (“No”/“Yes”) in one step.

See the solution 
clean <- clean %>% 
  mutate(across(
    # Transform all variables in the binary_cols vector
    .cols = all_of(binary_cols),
    # By transforming then into 0-1 factors with "No"-"Yes" labels
    # Base R version of transforming into factor
    .fns = ~ factor(., 
                    levels = c(0, 1),
                    labels = c("No", "Yes"))
  ))

#check
class(clean$diarrhoea)

Change food dose using a name pattern

For the food-dose variables, we can take advantage of the way they were named as they always include a final capital “D”. The helper function ends_with() becomes useful for this:

clean <- clean %>% 
  mutate(across(
    .cols = ends_with("D", ignore.case = FALSE),
    # Tidyverse version to convert into factor
    .fns = ~ as_factor(.)  
  ))

#check
class(clean$croquettesD)

The added the ignore.case argument to FALSE to force the function to differentiate between capital “D” and any d (default behavior). Because this time we were not interested in adding labels to the factor, we could rely on the tidyverse as_factor() function.

Action — Add the food-dose variable mutate to the cleaning pipe or update the clean object to keep the changes

Save and Export the cleaned dataframe

With these cleaning steps we can now save a new dataframe to continue working from it. Use the export() function with here() to define the path and filename. Because we created factors, the only format we can use is the R native format .rds

Action — Save the cleaned dataframe as carehome_clean1.rds in the clean data folder

export(clean, here("data", "clean", "carehome_clean1.rds"))
